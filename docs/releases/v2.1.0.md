# Twitter Hide Ads v2.1.0

## Promoted posts removed on every X surface

The render boundaries were already shared by every surface; this release makes the classifier recognise promoted posts wherever they appear, not only on the Home timeline.

### Changed

- Promoted posts are suppressed in post detail, search and every other surface that renders posts through the same Compose boundaries, not only the Home timeline.
- The URT `promoted-` entry token is matched at any `-` segment boundary instead of only at the start. Only the Home timeline names a promoted entry `promoted-tweet-<id>-<hash>`; a surface that nests the post inside a module prefixes that module's own entry, so the same advertisement arrives as `conversationthread-<id>-promoted-tweet-<id>-<hash>` in post detail and `search-conversation-<id>-promoted-tweet-<id>-<hash>` in search. These compound identifiers failed the previous prefix test and rendered.
- A promoted-metadata field is recognised by any runtime class name ending in `PromotedMetadata`, not only the validated `com.x.models.TimelinePromotedMetadata`, which X has obfuscated away since 12.22.0.
- Nested entry identifiers are accepted when choosing which string field carries the entry ID, so post-detail and search entries are logged instead of `unknown`.
- Classifier schema version raised from `6` to `7`.

### Verified

- X 12.23.1-prod.01 under Vector 2.2: 11 deoptimized boundaries installed, `enforcement=ACTIVE_ADAPTIVE`, promoted entries blocked before render on both the Home timeline and post detail, with normal posts and replies unaffected.

Video Tab dataset filtering is unchanged.

### Updating

Install the v2.1.0 APK over v2.0.0, then force-stop and reopen X once. Confirm the framework log reports `enforcement=ACTIVE_ADAPTIVE` and, while browsing, `Blocked promoted post before Compose`.
